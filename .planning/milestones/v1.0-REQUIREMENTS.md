# Requirements: KalExam YouTube RAG Bug Fix

**Defined:** 2026-03-02
**Core Value:** YouTube transcript chunks must survive page loads and be retrievable by the RAG pipeline

## v1 Requirements

### Backfill Fix

- [x] **BKFL-01**: Backfill sources includes YouTube URLs from Firestore source records, not just contextFiles
- [x] **BKFL-02**: `replaceIndexedChunks` called with YouTube chunks included when backfill triggers
- [x] **BKFL-03**: YouTube chunk documents in Firestore survive page reload without being deleted

### Cache Invalidation

- [x] **CACH-01**: `sourceTruthVersion` is incremented after a YouTube source is added via `handleAddSourceFromUrl`
- [x] **CACH-02**: Cached study content is regenerated with YouTube context after adding a YouTube source

### Verification

- [x] **VRFY-01**: RAG `getTopChunks` returns YouTube chunks when YouTube sources exist
- [x] **VRFY-02**: Generated study content references YouTube video material when YouTube sources are present

## v2 Requirements

### Robustness

- **RBST-01**: Race condition between loadSources and backfillSources is eliminated structurally (e.g., backfill waits for loadSources)
- **RBST-02**: URL-type sources also included in backfill (if applicable)
- **RBST-03**: Integration tests verify YouTube chunks persist across page loads

## Out of Scope

| Feature | Reason |
|---------|--------|
| Refactoring replaceIndexedChunks/appendIndexedChunks API | Working correctly; bug is in callers |
| Adding test infrastructure | Separate effort, no test framework exists |
| URL source type fixes | User unsure if broken; YouTube is the confirmed bug |
| Performance optimization of RAG retrieval | Not broken, just not receiving YouTube chunks |
| UI changes to source management | UI correctly shows chunk counts; the data layer is the problem |
