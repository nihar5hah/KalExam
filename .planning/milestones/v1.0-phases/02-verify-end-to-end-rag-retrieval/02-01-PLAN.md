**Prerequisites:** Have a study strategy with at least one topic and uploaded files.

**Test A: YouTube source addition + cache invalidation (VRFY-01 partial, VRFY-02)**

1. Open browser DevTools → Console tab
2. Navigate to a study topic page (e.g., `/study/some-topic`)
3. Wait for the page to fully load and study content to generate

5. Watch the Console for: `[YouTube-RAG-Verify] cache invalidated after source addition`
6. Observe that study content regenerates (loading indicator appears, new content loads)
7. The regenerated content should now reference or incorporate the video material

**Test B: Backfill preserves YouTube chunks across reload (VRFY-01)**

1. After Test A completes (YouTube source is added and visible in the sources list with a chunk count)
2. Hard-reload the page (Cmd+Shift+R / Ctrl+Shift+R)
3. Watch the Console for: `[YouTube-RAG-Verify] backfill detected YouTube URLs: N [urls...]`
   - N should be ≥ 1 (the video you just added)
   - This confirms backfill found the YouTube source and will include its URL in the re-index
4. After backfill completes, check the source list — the YouTube source should still show its chunk count (not 0)
5. Navigate to/regenerate study content — it should still reference video material

**Test C: RAG retrieval includes YouTube chunks (VRFY-01 definitive)**

1. Open the Network tab in DevTools
2. Trigger study content generation (click a topic or reload)
3. Find the `/api/study/topic` request in the Network tab
4. Check the response JSON — look for `usedVideoContext: true` in the response
5. If you want full retrieval debug info, you can add `?debugRetrieval=true` to the API call URL and check server logs for `[RAG] sources used:` with `youtubeChunks > 0`

**Expected outcomes:**
- Test A: Console shows cache invalidation log, content regenerates
- Test B: Console shows YouTube URLs detected in backfill, chunks survive reload
- Test C: API response includes `usedVideoContext: true`
